- 2026-10-10 — Final: the page reads check-ins through a Cloudflare Worker that queries the Notion API (token stored as a Worker secret) and caches the result for 60 seconds. Jill has a Cloudflare account. Why over the Notion Worker relay: the relay pattern rebuilds a site when something gets *published*, which suits jillmetcalfe.com. Writerjam just needs to *read* fresh data. A read proxy is 2 moving parts instead of 5 (no automation, no relay, no GitHub token to expire, no deploy per check-in), and check-ins show within a minute. The page shows the last good data if the Worker fails.
- 2026-10-11 — The Worker finds the name field by its type (the title property), not its label, because Jill renamed "Handle" to "Your name" in the form. Renaming it again won't break the page.

Removing it is a one-line change in `index.html` (search for `nofollow`) if Jill wants to pass on search credit later. Expect only a small benefit either way: links are drawn by JavaScript and the domain is new.
